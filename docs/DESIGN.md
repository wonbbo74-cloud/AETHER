## 1. 진행 구조

```text
04 벙커(튜토리얼) → 05 폐허된 도시 → 06 연구소 → 07 파츠 제작실
   → 08 1구역 → 09 2구역 → 11 3구역(최종)
```

| 구역 | 얻는 파츠 재료 | 다음 구역과의 연결 |
|---|---|---|
| 05 폐허된 도시 | 슈퍼 점프 | 1구역 점프 코스를 건너는 데 필요 |
| 08 1구역 | 방패 | |
| 09 2구역 | 브레이커 | |
| 11 3구역 | 없음 | 최종 구역 |

- 파츠 재료를 모아 제작실에서 만들고 장착해야 다음 구역을 공략할 수 있게 해, **수집 → 제작 → 새 능력으로 다음 구역 진입**이 한 사이클이 되도록 했습니다.
- 구역의 적을 모두 처치하면 클리어가 기록되고 엘리베이터의 다음 층 버튼이 열립니다.

근거: `PartsSystem/PartSceneModuleBootstrap.cs`, `SceneFlow/AetherZoneProgressDirector.cs`

## 2. 성장: 에테르 레벨

한 판 동안 처치·퍼즐·수집·제작으로 에테르를 모으고, 레벨이 오르면 실제로 강해집니다.

| 행동 | 에테르 |
|---|---|
| 로봇 / 터렛 / 드론 처치 | 60 / 90 / 35 |
| 아이템 줍기 / 설계서 줍기 | 12 / 80 |
| 파츠 제작 | 150 |
| 블록 퍼즐 / 회로 퍼즐 | 250 / 300 |

| 레벨 | 누적 에테르 | 효과(누적) |
|---|---|---|
| Lv2 | 300 | 최대 체력 +20, 공격력 +10% |
| Lv3 | 900 | 자연 회복 +4/초, 회복 시작 5초 → 4초 |
| Lv4 | 1,800 | 최대 체력 +40, 받는 피해 -10% |
| Lv5 | 3,000 | 공격력 +25%, 받는 피해 -15% |

설계 의도
- **어떤 플레이 스타일이든 성장이 보이게:** 05에서 거의 다 싸우면 05 끝에 Lv4, 07 제작 후 Lv5가 됩니다. 싸움을 피하고 퍼즐·수집 위주로 가도 Lv4 정도까지 오릅니다.
- **첫 레벨업을 일찍:** 04 퍼즐만 깨도 Lv2로 05에 들어갑니다.
- **역전의 순간:** 05의 적이 몰린 구간에서 레벨이 오르면 체력이 가득 차서, 밀리던 싸움을 뒤집을 수 있습니다.
- **연속 처치 보상:** 6초 안에 다음 적을 쓰러뜨리면 획득 배율이 0.25씩 올라 최대 ×2가 됩니다. 싸움을 끊지 않고 이어 가는 재미를 줍니다.
- **반복 파밍 방지:** 같은 적·물건·퍼즐은 한 판에 한 번만 에테르를 줍니다.

근거: `SceneFlow/AetherLevel.cs`

## 3. 전투 밸런스 조정

플레이테스트에서 관찰한 문제와 조정 결과입니다. 조정 값은 `AetherCombatBalance` 한 곳에 모아, 숫자 하나만 바꿔도 모든 적에 반영되게 했습니다.

| 항목 | 관찰한 문제 | 조정 | 의도 |
|---|---|---|---|
| 플레이어 최대 체력 | 씬에 저장된 값이 로봇과 같은 100 | 100 → **200** | 로봇의 두 배로 두어 여러 적을 상대할 여유 확보 |
| 적 총알 피해 | 05 시작 지점에 서 있으면 7초에 78이 깎여 9초 만에 사망 | **×0.6** | 엄폐하고 반격할 틈 확보 |
| 로봇 소총 피해 | 사방에서 맞으면 감당이 안 됨 | **×0.35** | 거치형 터렛은 묵직하게, 들고 쏘는 소총은 가볍게 |
| 받는 피해 전체 배율 | 처음엔 공격이 너무 셌고, 체력 200·자연 회복과 겹친 뒤에는 HP가 거의 닳지 않아 긴장감이 사라짐 | 0.6 → 1.0 → 1.3 → 2.6 → **5.2** | 테스트마다 단계적으로 올려 긴장감 회복 |
| 자연 회복 | 초당 8은 맞은 만큼 금방 차서 HP가 안 닳는 것처럼 보임 | 8 → 5 → **3.5/초** | 엄폐 → 회복 → 반격의 흐름은 유지하되 피해가 남게 |
| 갈증 감소 | 초당 0.2면 05 중간에 갈증이 바닥나 회복이 멈추고, 물 3병으로도 모자람 | 0.2 → **0.1/초** | 가득 찬 갈증이 약 17분, 물 한 병이 약 7분 유지 |
| 터렛 감지 거리 | 34m에서는 잔해에 가려 안 보이는 터렛이 총알만 보냄 | 34 → 22 → **40m** + 가림 판정 | 멀리서도 위협하되, 보이지 않는 터렛은 쏘지 않게 |
| 터렛 발사 간격 | 0.65초면 터렛 넷의 총성이 겹쳐 빗소리처럼 들림 | 0.65 → **2.1초** | 한 발 한 발이 '뻥' 하고 읽히게 |
| 연구소 문 표적 | 한 발에 다음 표적으로 넘어가 너무 쉬움 | 1발 → **3발** | 표적마다 여러 번 맞혀야 넘어가게 |

근거: `SceneFlow/AetherCombatBalance.cs`, `Player/PlayerStatus.cs`, `Lab_DoorPointer.cs`

## 4. 교전 흐름: 웨이브 설계

**문제:** 05 폐허된 도시의 시작 지점 10~40m 안에 로봇 14·드론 7·터렛 4가 몰려 있어, 들어서자마자 모두가 한꺼번에 덤볐습니다.

**설계:**
- 시작 지점 근처(45m) 적은 처음엔 '대기' 상태로 두고 웨이브로 하나씩 깨웁니다.
- 가까운 일반 로봇부터 먼저 나오고, 드론·중장비·터렛은 뒤 웨이브에 나옵니다. 웨이브 크기는 2 → 3 → 4 → 5로 늘어납니다.
- 앞 웨이브가 거의 정리되면(깨어 있는 적 1기 이하) 다음 웨이브가 옵니다. 너무 오래 끌면 35초 뒤에 강제로 옵니다.
- 웨이브가 진행될수록 받는 피해가 ×0.8에서 최대 ×1.2까지 커집니다.
- 대기 중인 적도 플레이어가 쏘거나 7m 안으로 다가오면 깨어납니다. 몰래 지나가는 플레이는 허용합니다.
- 시작 지점에서 먼 적(공장 가는 길)은 그대로 두어, 걸어가며 차례로 만나게 합니다.

근거: `SceneFlow/AetherEncounterDirector.cs`

## 5. 이동과 레벨 디자인: 슈퍼 점프

**문제:** 최대 힘 42로는 풀충전 시 58m를 날아가 맵 밖으로 넘어갔습니다.

**조정:** 높이는 힘의 제곱에 비례하므로 최대 힘을 **25(약 20m)**로 제한했습니다. 씬마다 저장된 값이 달라도 이 값을 넘지 않습니다.

**1구역 점프 코스 설계:**
- 플레이어 키 1.55m, 달리기 6m/s이고 공중에서도 같은 속도로 움직입니다.
- 건널 수 있는 거리 = 도달 높이로 정해지는 체공 시간 × 6m/s 입니다.

| 도달 높이 | 체공 시간 | 건너는 거리 |
|---|---|---|
| 2m(최소 충전) | 약 1.3초 | 약 8m |
| 14m(최대 충전, 1.2초) | 약 3.4초 | 약 20m |

- 발판 사이 간격은 **14m 이하**, 오르막은 **4m 이하**로 잡았습니다. 충전을 가늠하면 넘어가고, 대충 누르면 떨어지는 난이도입니다.
- 떨어지면 직전 발판으로 되돌려 반복 시도 부담을 줄였습니다.

근거: `PartsSystem/HangyeolPartAbilityController.cs`, `SceneFlow/AetherZone1Director.cs`

## 6. 퍼즐과 난이도 자동 조절(DDA)

플레이어가 막히면 개입 시점에 맞춰 힌트를 단계적으로 늘립니다. 개입 시점은 Early / Normal / Late 세 가지로 조절할 수 있습니다.

**회로 연결 퍼즐**

| 개입 시점 | 단계가 오르는 조건 |
|---|---|
| Early / Normal / Late | 틀린 게이트를 2 / 3 / 4번 고를 때마다 |

| 단계 | 도움 |
|---|---|
| 1단계 | 잘못 고른 게이트를 꺼서 다시 고르지 않게 함 |
| 2단계 | 정답 게이트가 있는 방향 힌트 추가 |
| 3단계 | 열마다 오답 게이트의 30%를 꺼서 선택지를 줄임 |

**코드 해독 퍼즐(숫자야구)**

| 개입 시점 | 단계가 오르는 조건 |
|---|---|
| Early / Normal / Late | 스트라이크가 늘지 않은 제출이 2 / 3 / 5번 이어질 때 |

| 단계 | 도움 |
|---|---|
| 1단계 | 정답에 없을 가능성이 높은 숫자 3개 표시 |
| 2단계 | "n번째 자리는 입력한 숫자보다 큽니다/작습니다" 비교 힌트 |
| 3단계 | "n번째 자리의 정답은 ○입니다" 일부 자리 공개 |

- 레벨이 오를 때마다 퍼즐 제한 시간이 5초씩 늘어나, 전투 성장이 퍼즐 난이도 완화로도 이어지게 했습니다.

근거: `Puzzle/Puzzle2/Puzzle2DDAController_Final.cs`, `Puzzle/Puzzle3/Puzzle3DDAController_Final.cs`, `SceneFlow/AetherLevel.cs`
